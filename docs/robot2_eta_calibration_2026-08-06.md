## 1. 최종 요약

Robot2의 Nav2 전역 경로를 이용해 예상 도착시간을 계산하고 실주행으로
보정했다. 1차 짧은 경로 실험에 이어, 2차 실험에서는 반대 방향 주행과
3~4m급 복합 경로를 측정했다. 3차 실험에서는 중앙 벽 경로를 재측정하고
4.46m 상단 횡단 경로로 추가 검증했다.

최종 보정값은 다음과 같다.

| 항목 | 1차 값 | 최종 값 |
|---|---:|---:|
| 기준 선속도 | 0.15m/s | **0.20m/s** |
| 기준 각속도 | 1.0rad/s(임시) | **0.70rad/s** |
| 이동 중 큰 코너 페널티 | 0초(임시) | **4.0초/개** |
| 경로 단순화 허용오차 | 0.05m | **0.10m** |

추가 상단 횡단 검증에서는 예측 22.83초, 실제 23.50초로 오차가
+0.67초였다.

## 2. 현재 ETA 계산식

```text
ETA = Nav2 경로 길이 / 0.20m/s
    + 총 회전각 / 0.70rad/s
    + 이동 중 45° 이상 코너 개수 × 4.0초
```

총 회전각에는 다음 세 항목을 모두 포함한다.

```text
총 회전각 = 시작 yaw → 첫 경로 방향
          + 단순화된 경로 내부 회전
          + 마지막 경로 방향 → 목표 yaw
```

코너 페널티는 단순화된 경로 내부의 45° 이상 코너에만 적용한다. 출발
제자리 회전과 목표 yaw 정렬은 이미 각속도 비용으로 계산되므로 코너
페널티를 중복 적용하지 않는다.

## 3. 실험 환경

- 로봇: TurtleBot 4 `robot2`
- 상태: 언도킹, 도크가 보이지 않는 위치
- 전역 경로 계획기: Nav2 `GridBased`(NavFn)
- 지역 제어기: DWB Local Planner
- 지도: `aed_bringup/maps/map.yaml`
- 실제시간 측정: 최초 `EN_ROUTE`부터 `ARRIVED`까지
- 경로 단순화: Ramer-Douglas-Peucker
- 주행 전 통신 상태
  - Robot2 ping: 손실 0%, 평균 약 12.8ms
  - `/robot2/scan`: 약 7.3Hz
  - `/robot2/odom`: 약 20Hz
- 3차 재부팅 후 통신 상태
  - Robot2 ping: 손실 0%, 평균 약 3.4ms
  - `/robot2/scan`: 안정화 후 약 6.9Hz
  - `/robot2/odom`: 약 20Hz

2.9%)였다. 중앙 벽 경로는 세 번 모두 편차가 커서 경로 형상 외의
costmap·TF·제어 지연 영향을 별도로 다뤄야 한다.

## 5. DWB 반대 방향 주행 수정

기존 설정은 다음과 같았다.

```yaml
min_vel_x: -0.10
max_vel_x: 0.20
vx_samples: 20
```

이 범위를 20개로 샘플링하면 `vx=0`이 정확한 후보에 포함되지 않는다.
뒤쪽 경로를 향해 제자리 회전해야 할 때 조금씩 전진하거나 후진하는
궤적만 만들어져 `no path progress`가 발생할 수 있었다.

다음과 같이 수정했다.

```yaml
min_vel_x: 0.0
```

수정 후 0.80m 반대 방향 경로에서 제자리 회전 후 전진했고 11.16초 만에
정상 도착했다. 따라서 반대 방향 주행 문제는 언도킹 상태에서 검증됐다.

이 값은 DWB `FollowPath`에만 적용된다. Create 3의 `/undock` 액션과 Nav2
복구 동작 `BackUp`은 별도 제어이므로 후진 기능이 유지된다.

## 6. 경로 회전량 보정

NavFn 경로는 격자 단위로 조밀한 점을 생성한다. 이를 그대로 사용하면
작은 좌표 흔들림도 회전으로 누적된다.

153개 점으로 구성된 복합 경로의 단순화 결과는 다음과 같았다.

| 허용오차 | 남은 점 | 내부 회전량 | 45° 이상 내부 코너 |
|---:|---:|---:|---:|
| 0.02m | 13개 | 353.9° | - |
| 0.05m | 9개 | 232.1° | 2개 |
| 0.08m | 6개 | 153.2° | 0개 |
| 0.10m | 5개 | 141.8° | 1개 |
| 0.15m | 5개 | 141.8° | 1개 |

0.10m부터 경로 형상이 안정됐으므로 최종 허용오차를 0.10m로 정했다.

## 7. 왕복 시간 편차 분석

거의 동일한 중앙 벽 우회 경로가 왕로 41.56초, 복귀 23.77초로 약 18초
차이를 보였다. 거리와 경로 회전량만으로는 이 편차를 완전히 설명할 수
없다.

왕로 직전 Nav2 로그에는 다음 메시지가 반복됐다.

```text
Message Filter dropping message:
the timestamp on the message is earlier than all the data in the transform cache
```

즉 scan/TF 시각 불일치로 costmap과 AMCL 입력 일부가 폐기됐으며, 일시적인
감속 또는 재계획 지연이 왕로 시간에 포함됐을 가능성이 높다. 현재 ETA는
정상 통신 상태의 기하학적 경로 비용을 계산하며, 네트워크·TF 지연은 별도
신뢰도 페널티로 확장하는 것이 적절하다.

## 8. 파라미터 산출 방법

다음 선형 모델로 성공 데이터를 최소제곱 적합했다.

```text
실제시간 = 경로거리 × 초/m
         + 총 회전각 × 초/rad
         + 내부 큰 코너 개수 × 페널티
```

적합 결과:

- 선속도: 약 0.197m/s
- 각속도: 약 0.688rad/s
- 내부 큰 코너 페널티: 약 3.89초

설정과 로그 가독성을 위해 각각 `0.20`, `0.70`, `4.0`으로 반올림했다.

## 9. 자동 측정 로그

성공 시 다음 로그를 자동 출력한다.

```text

```

실패 시 경과시간과 원인을 기록한다.

```text
ETA measurement robot2: aborted after 30.12s (no path progress for 30.0s)
```

### 추가 실험 중 중복 제어 노드 확인

3차 측정 당시 종료되지 않은 이전 `central_dispatch.launch.py`가 별도로
남아 있었다. 그 결과 `robot2_mission_executor`가 두 개가 되어 동일한
Nav2 목표가 중복 전송됐고 다음 현상이 함께 나타났다.

- Nav2의 `Received goal preemption request`
- 실제 주행 직후 잘못된 `Nav2 status=6`
- 이후 실제 Goal의 정상 `ARRIVED`

중복 런치 PID와 자식 executor를 종료한 뒤 관련 프로세스가 남지 않은
것을 확인했다. 7·8회 실제시간은 중앙 노드의 잘못된 실패 상태가 아니라
Nav2의 최종 Goal 시작 시각부터 `Reached the goal`까지를 기준으로
계산했다. 이후 측정 전에는 다음 명령으로 중앙 노드가 하나뿐인지 먼저
확인해야 한다.

```bash
pgrep -af 'emergency_mission_manager|mission_executor|central_dispatch'
```

## 10. 현재 결론

- Nav2가 생성한 실제 전역 경로 길이를 사용한다.
- 시작 yaw, 경로 내부 회전, 목표 yaw 정렬을 모두 ETA에 포함한다.
- 경로 단순화 허용오차는 0.10m다.
- DWB는 일반 경로에서 후진하지 않고 제자리 회전 후 전진한다.
- 최종 선택 기준은 최소 거리 대신 최소 ETA다.
- 최신 상단 횡단 검증 경로 오차는 약 0.67초였다.
- scan/TF 지연이 발생하면 경로 기하만으로 실제시간을 정확히 예측하기
  어렵다.
- 중앙 런치를 중복 실행하면 동일 목표 preemption과 잘못된 실패 상태가
  발생하므로 실행 인스턴스를 하나로 유지해야 한다.
