# 누운 대상의 관절 검출 — 실측 기록과 다음 작업

2026-08-07. 목각인형을 카메라 1번(고정 웹캠, 640x480) 앞에 두고 잰 값이다.
이 문서는 `rotated_pose.py` 가 왜 필요했는지와, 이어서 무엇을 해야 하는지를
남긴다.

## 1. 문제

목각인형이 **누우면** 사전학습 YOLO Pose 가 관절을 못 잡는다. 그런데 우리가
찾아야 하는 것이 바로 그 자세다.

| 조건 | person conf | 관절(>0.5) |
|---|---|---|
| 원본 640x480 그대로 | 검출 없음 | — |
| imgsz 1280 까지 올림 | 검출 없음 | — |
| 모델 확대 (n → s → m → l) | **전부 검출 없음** | — |
| 크롭 후 6배 확대 | 검출 없음 | — |
| **90도 돌려서** | **0.875** | **17/17** |

크기 문제가 아니다. 6배로 키워도 안 되고 모델을 l 까지 키워도 안 된다.
**방향**이 문제다. 30도 간격으로 한 바퀴 돌려 재면 이렇게 나온다.

| 각도 | 0 | 30 | 60 | **90** | **120** | 150 | 180 | 210~330 |
|---|---|---|---|---|---|---|---|---|
| conf | 0.10 | 0.13 | 0.25 | **0.89** | **0.83** | 0.07 | 0.14 | 0.05~0.08 / 없음 |

머리가 위로 오는 90~120도에서만 잡힌다. COCO 는 서 있는 사람으로 배웠고
YOLO 는 회전 불변이 아니다.

## 2. 해법과 함정

박스를 잘라 세워서 관절을 얻는다. **다만 세운 좌표를 그대로 쓰면 안 된다.**

| | 종횡비 | 코의 상대 y |
|---|---|---|
| 세운 상태의 bbox 그대로 | 0.40 (서 있음) | 0.08 |
| **역회전해 원본 좌표로** | **2.66 (누움)** | **0.72** |

세운 좌표를 쓰면 "서 있는 사람"이 되어 자세 판정 근거가 사라진다.
`pose_posture.classify_posture()` 가 종횡비와 몸통 각도를 보기 때문에,
회전 행렬의 역행렬로 **원본 좌표계에 되돌려야** 한다. 회전은 어파인 변환이라
가역이고, 6배 확대 후 돌리므로 보간 오차는 원본 픽셀의 1/6 이다.

## 3. 만든 것

- **`rotated_pose.py`** — 박스를 잘라 6배 확대 → 0/90/270도 회전 → Pose 추론
  → 관절을 원본 좌표로 복원. `(17, 3)` 으로 돌려주므로 `classify_posture()` 에
  그대로 넣을 수 있다. 판정 규칙은 새로 만들지 않고 기존 것을 쓴다.
- **`rotated_pose_test.py`** — 같은 프레임에 "회전 없이"와 "세워서"를 나란히
  돌려 비교한다.

```bash
cd vision_training/testing
python3 rotated_pose_test.py                          # 웹캠, 화면 표시
python3 rotated_pose_test.py --frames 100 --no-show   # 숫자만
python3 rotated_pose_test.py --source shot.jpg        # 이미지 한 장
```

각도 후보는 박스 모양으로 순서를 정한다(가로로 길면 90도부터). 후보를 줄이지는
않아서 넘어지는 중처럼 애매한 구간에서도 세 각도를 다 본다. 몸통 네 점을
확보한 후보를 우선하고, 그중 conf 가 0.6 을 넘으면 남은 각도를 건너뛴다.
`(몸통 확보, conf)` 순으로 고르지 않으면 관절 3개짜리 후보에서 멈춰 버린다.

## 4. 결과

| 프레임 | 회전 없이 | 세워서 |
|---|---|---|
| 뻗어 누움 (테이프 전) | 검출 0/1 → UNKNOWN | **1/1 → FALLEN** (90도) |
| 뻗어 누움 (테이프 후) | 1/1 → FALLEN | 1/1 → FALLEN (90도) |
| 서 있음 (웹캠 30프레임) | 30/30 → STANDING | 30/30 → STANDING (**0도**) |

서 있을 때는 0도가 선택되어 두 방법이 같다. 회전 때문에 서 있는 사람을
쓰러졌다고 하는 일은 없었다.

속도는 두 방법을 합쳐 프레임당 29 ms(RTX 4070). 방법별로는 이렇다.

| 방식 | ms/frame |
|---|---|
| rescue 만 (640) | 4.9 |
| pose 원본만 (960) | 8.5 |
| rescue + 3각도 전탐색 | 48.3 |
| rescue + 조기 종료 | 27.4 |
| rescue + 각도 1개 선택 | 20.1 |

카메라가 15 fps(66 ms 주기)라 어느 쪽이든 들어간다.

## 5. 곁가지로 확인된 것

**검은 테이프.** 인형 머리가 몸통과 같은 밝은 나무색이라 머리 위치 단서가
없었다. 머리를 검게 감싸 부피를 두 배로 하면 회전 없이도 conf 0 → 0.382 가
된다(10프레임 중 1프레임). 눈·입을 그리는 것은 무의미하다 — 머리가 8.4 px
이라 눈 하나가 1.7 px 이고, 흰 눈은 오히려 검출을 죽였다. 색은 검정 > 어두운
갈색 > 빨강 > 파랑 순이고 흰색·살구색은 검출 실패. 크기는 반지름 8 px
(몸의 0.4배)에서 정점, 12 px 부터 다시 떨어진다.

**rescue 모델의 자세 구분.** `rescue_yolo11n` 은 서 있는 인형을 잡지 않았다
(0/10). 자세를 구분한다. 다만 **머리에 검은 테이프를 감은 뒤로는 서 있는데도
6/10 으로 오탐**했다(conf 0.325). 학습 데이터에 검은 머리가 없어서로 보인다.

**`omnifall_yolo11n_pose_lstm_best.pt` 는 관절 모델이 아니다.** BiLSTM 시계열
분류기이고, 관절은 사전학습 `yolo11n-pose.pt` 에서 나온다
(`training/caterpillar_fall_pose_colab.ipynb` 의 `pose_model = YOLO('yolo11n-pose.pt')`).
학습 데이터가 OmniFall OF-Synthetic 영상(사람이 화면 가득)이라 거기서는
누워도 관절이 잡혔지만, 103x39 px 목각인형에서는 안 잡힌다. **FALLEN 구간에서
관절이 끊기면 LSTM 은 정작 판정해야 할 순간에 입력을 못 받는다.**
`vision_training/README.md` 의 "12관절 Pose 라벨 검사"는 이번 커밋에서 삭제된
옛 `notebooks/` 얘기라 현재 노트북과 맞지 않는다.

# 다음 작업 (Codex 에게)

아래는 검증된 사실 위에서 이어서 할 일이다. 순서대로 하면 된다.

## A. 자동 라벨을 모아 Pose 를 파인튜닝한다 (본 과제)

회전 TTA 는 우회로다. 추론이 3배로 늘고, 넘어지는 중(각도 45도 부근)에서
어느 각도를 골라야 할지 애매하다. 근본 해결은 **누운 자세를 회전 없이 바로
잡는 모델**이다.

손으로 관절을 찍을 필요는 없다. `rotated_pose.estimate()` 가 그대로 라벨
생성기가 된다.

1. 인형을 여러 위치·각도·자세로 두고 프레임을 모은다. 카메라 1번 고정 웹캠,
   640x480, 실제 배포와 같은 조건이어야 한다.
2. 각 프레임에서 `rescue_yolo11n` 으로 박스를 얻고 `rotated_pose.estimate()`
   로 관절을 얻는다. **채택 기준**: person conf ≥ 0.7 이고 몸통 네 점이 모두
   0.5 이상. 나머지는 버린다.
3. YOLO Pose 학습 형식으로 저장한다. `kpt_shape: [17, 3]`, `flip_idx` 는
   `pose_data.example.yaml` 의 것을 그대로 쓴다.
4. `training/yolo_train_pose.py` 로 `yolo11n-pose.pt` 에서 파인튜닝한다.
5. `rotated_pose_test.py --detector-weights none` 으로 **회전 없이** 누운
   인형이 잡히는지 확인한다. 이게 성공 판정이다.

주의할 것:

- **분할은 세션 단위로 한다.** 같은 세션의 연속 프레임이 train 과 val 에
  나뉘면 성능이 부풀려진다.
- 얼굴 5점(코·양눈·양귀)은 8.4 px 머리에서 원리적으로 안 잡힌다. 실측에서
  0.22~0.34 로 전부 임계 미달이었다. **몸통·팔다리 12점만 라벨로 쓰는 것을
  검토하라.** 무리하게 얼굴을 넣으면 학습이 흔들린다.
- 데이터를 모을 때 **머리에 검은 테이프를 감은 상태와 아닌 상태를 모두**
  포함해야 한다. 배포 시점의 인형 모습과 학습 데이터가 같아야 한다.

## B. rescue 모델의 오탐을 확인한다

머리에 검은 테이프를 감은 뒤 서 있는 인형을 6/10 으로 오탐했다(conf 0.325).
테이프를 떼고 다시 재서, 테이프가 원인인지 확정하라. 원인이 맞다면 A 의
데이터 수집 때 rescue 재학습분도 같이 모아야 한다.

## C. 파이프라인에 이식한다 (A 가 끝난 뒤)

`src/aed_vision` 은 이번에 건드리지 않고 되돌렸다. 검증이 끝나면 옮긴다.
시험 삼아 붙였을 때 25초 362프레임에서 이렇게 나왔다.

- rescue 가 서 있는 인형을 **362/362 오탐**
- 자세 판정이 **362/362 성공** (STANDING 353 / LYING 9, 회전각 전부 0도)
- **`fallen_confirmed` 0/362** — 자세 관문이 오탐을 전부 걸렀다
- 추론 평균 22 ms, 최대 52 ms

이식할 때 지킬 것:

- `pose_weights` 가 비면 **기존 동작 그대로**여야 한다. 자세 판정은 선택 기능이다.
- 자세를 **판정하지 못했을 때(UNKNOWN)는 막지 않는다.** 판정 실패를 근거로
  사고를 놓치면 안 된다. 막는 것은 `STANDING` 으로 확정했을 때뿐이다.
- `status` 토픽에 `posture`, `torso_angle_deg`, `pose_conf`, `pose_keypoints`,
  `pose_rotation_deg` 를 실어 사후에 판단 근거를 되짚을 수 있게 한다.

## D. 넘어지는 중(FALLING)을 확인한다

지금 검증은 "서 있음"과 "누움" 두 정지 상태뿐이다. 인형을 천천히 눕히면서
프레임 단위로 기록해, 전이 구간에서 회전각 선택이 흔들리는지 보라. 종횡비가
1 부근일 때 어느 각도를 고르는지가 관건이다. 이 구간이 가장 빨리 알아야 하는
순간이다.
